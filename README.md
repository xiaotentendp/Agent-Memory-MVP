# Agent 经验记忆 MVP：写入门控、防篡改与失败归因

一个面向大语言模型 Agent 的经验记忆管理最小可运行验证（MVP）。

## 解决什么问题

Agent 从交互中积累经验时，有三个容易被忽视的风险：

1. **记忆投毒**：外部不可信输入（网页、邮件、文档）诱导 Agent 执行动作，若该交互被当作"成功经验"沉淀，后续同类输入会自动匹配到这条经验，形成持久化后门。
2. **经验被篡改**：记忆被压缩存储后与原始记录脱钩，一旦存储被改写，系统无从发现。
3. **正确经验被噪声压垮**：失败信号不加区分地计入降权，一条正确的经验会在有噪声的真实环境中被逐步压低直至废弃。

本 MVP 针对这三个问题，实现了三条主线：写入门控、分层记忆与防篡改、失败归因与衰减。

## 核心机制

### 1. 写入门控（三重条件）

一条交互要被固化为经验，必须同时满足：

- **来源可信**：动作参数值不直接取自不可信文本（硬污点拦截）；
- **通过安全网关**：动作在白名单内、不违反安全基线、参数在合法区间、动作与对象匹配当前任务；
- **执行成功**。

任一条件不满足，不生成经验记录，只进审计日志。含软污点（存在不可信来源但参数不构成直接嵌入）的交互降级为**候选经验**，不参与自动检索。

### 2. 分层记忆与防篡改

- **中层指针库**：只存指针、摘要、权重、档位与完整性哈希，不存完整交互文本。
- **底层日志库**：完整交互记录，链式哈希串联，仅追加。
- **哈希双份存放**：中层指针的完整性哈希同时另写一份到底层。检索前重算中层哈希并与底层比对，中层被篡改即可被发现。

### 3. 失败归因与衰减

经验被调用后出现异常，先归因再处置：

- **经验自身不安全**（动作不在白名单 / 违反基线 / 参数超出区间）：跳过阈值，直接隔离。
- **任务不匹配**：只记审计日志，不改权重、不隔离。
- **执行失败**：区分动作性失败（降权，低于阈值隔离）与环境性失败（不降权，只记日志）。

成功的调用按步长回升权重，上限为初始权重。
